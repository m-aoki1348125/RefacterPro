# リスク分類 (Risk Taxonomy) — 正典

リファクタリング操作を Tier 0–3 に分類する。wave-planner は plan.md の全タスクに Tier を明記し、
refactor-worker は割当タスクの Tier を超える操作をしてはならない(発見したら部分完了で報告)。
Tier ごとの必須ゲートは下表の通り([workflow.md](workflow.md) §6 のゲート定義を参照)。

| Tier | 性質 | 例 | 必須ゲート |
|---|---|---|---|
| **0** 自動 | 構文的・機械的で挙動に触れない | コードフォーマット、ローカル変数 rename、extract function / extract constant(同一ファイル内)、コメント・docstring 追記、import 整理(挙動非依存が自明な場合) | 機械ゲート G1–G6, G8 |
| **1** 自動+検証 | モジュール内で意味が閉じる再編 | モジュール内 rename(公開名以外)、extract class、ファイル分割・移動(モジュール内)、テスト追加、型注釈追加 | 機械ゲート + G7 (verifier) |
| **2** 自動+検証+特記 | 境界に触れるが旧挙動を温存できる再編 | モジュール境界の再編(**旧 API を facade として温存する二段階変更**)、重複コード統合、**証拠付き**デッドコード削除(下記)、グローバル状態の注入化(呼び出し互換を維持) | 機械ゲート + G7 + report.md に特記 |
| **3** 人間承認 | 外部から観測可能な挙動・契約に触れる | 外部 API / CLI フラグ / 入出力フォーマットの変更、DB スキーマ、並行性・ロック・順序、エラー処理セマンティクス、性能クリティカルパス、facade の最終除去、フェンス解除を伴う変更 | 実行前に項目ごと AskUserQuestion + 全ゲート |

## 補則

### 証拠付きデッドコード削除(Tier 2 止まり、Tier 0 にしない)

削除には以下**すべて**の証拠を wave-NN.md に記録すること:

1. 静的参照ゼロ: 全リポジトリ grep(識別子そのもの+文字列リテラルとしての出現)
2. 動的呼び出しパターンの検査: `getattr` / リフレクション / 文字列ディスパッチ / 設定ファイル駆動 /
   eval 系 / コマンドテーブル。**識別子が文字列として現れる場合は削除禁止**
3. エントリポイントからの到達性解析(dependencies.md と突合)
4. `git log` でその関数の最終変更と導入意図を確認

ひとつでも UNKNOWN が残るなら削除せず fences.md 行き。動的言語では「grep で見つからない」は
「呼ばれていない」を意味しない。

### 公開シグネチャ・スナップショット

Wave 前後で公開 API(exported symbols / 関数シグネチャ / CLI フラグ)を比較し、
変化があればそのタスクは自動的に Tier 3 扱い(停止して人間承認)。
facade 温存(Tier 2)は「旧シグネチャが残っていて委譲する」ことを意味する。

### Chesterton's Fence

- 目的を一次証拠付きで説明できないコード(奇妙な sleep、説明のない順序依存、意味不明な定数、
  用途不明の分岐)は fences.md に登録し、**worker の fileset から除外**する。
- フェンス登録ファイルへの変更は G5 で機械的に検出される(fileset に入っていないため)。
- 解除は人間のみ。解除記録には「なぜ存在したかが判明した理由」と日付を記入する。
- worker が作業中に新たな説明不能コードに遭遇したら: 触らず、フェンス追加候補として報告し、
  該当タスクを部分完了で返す。
